# Working rules for this project

## How to work with me
- Make every file change with Edit/Write so it appears as a diff in the editor for me to
  accept. Never modify, move or delete project files through Bash (python, sed, heredocs,
  cat >>, mv, rm). Ask before deleting or regenerating files.
- After a change, show the key code or a short diff in the reply.
- Work in stages. Do only the current stage, then stop, show what was done and how to run
  it, and wait for my go-ahead.
- Keep it simple, readable and well tested; avoid over-engineering; explain each design
  choice briefly. 
- Do not call the Claude API (or anything that costs money) until I say so.

## Project rules
- Python 3.12, uv only: `uv add` for dependencies, `uv add --dev` for dev tools, `uv run`.
- Never commit PDFs, extracted report text or secrets. data/raw/ and data/processed/ are
  git-ignored. API keys only via environment variables (ANTHROPIC_API_KEY), loaded locally
  with `uv run --env-file .env`; never print or log them.
- Never invent results. Every number in the README must come from code I can run
  (evaluation tables are generated by `python -m rag.eval.report`).
- Layout: src/rag/ (package), tests/, data/ (raw/, processed/), eval/, scripts/, results/.
- Tests for each module (no network, no model downloads), small functions,
  `uv run ruff check .` and `uv run pytest` must pass.
